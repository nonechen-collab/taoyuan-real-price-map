# 資料字典

> 欄位、單位與公式。原始欄位以內政部實價登錄開放資料為準（每期 zip 內附 schema-*.csv）。

## 單位約定

| 項目 | 單位 | 換算 |
|---|---|---|
| 面積 | 坪 | m² × 0.3025 |
| 金額 | 萬元 | 元 ÷ 10,000 |
| 單價 | 萬/坪 | （元 ÷ 10,000）÷（m² × 0.3025）；與官方「元/m²」的關係：萬/坪 × 3,025 ＝ 元/m² |
| 日期 | 西元 | 民國年 + 1911；「1150821」→ 2026-08-21；日為 00 時當 1 日 |
| 屋齡 | 年（小數一位） | （交易日 − 建築完成年月）÷ 365.25；預售屋無屋齡（篩選時視為 0 年） |

## 計算公式

| 指標 | 公式 | 說明 |
|---|---|---|
| 權狀坪（不含車位） | 建物移轉總面積 − 車位移轉總面積 | 坪數篩選、統計卡「坪數中位」用這個 |
| 室內坪 | 主建物面積 | 預售表沒有主建物欄位 → 無資料 |
| 公設面積 | 權狀（不含車位）− 主建物 − 附屬建物 − 陽台 | 實測陽台**不含**在附屬建物（2026-10-18，見 SPEC 決策紀錄）；算出負值超過 5% 視為資料有誤、不顯示 |
| 公設比 | 公設面積 ÷ 權狀（不含車位） | |
| 扣車位單價（主要顯示） | （總價 − 車位總價）÷（建物移轉總面積 − 車位面積） | 統計、色階、篩選都用這個 |

### 與官方「單價元平方公尺」的差異規則

實測（115S3＋本期，買賣 6,195 筆、預售 2,077 筆）：

- **車位有拆價**：官方單價 ＝（總價 − 車位價）÷（建物面積 − 車位面積），與本站扣車位單價**完全相同**（100% 吻合，萬/坪 × 3,025 即官方值）
- **車位未拆價**（有車位但車位價 0）：官方單價 ＝ 總價 ÷ 建物總面積（含車位面積），等於把車位當成和房子同價 → 本站改用估算扣除（下節），兩者會不同，卡片標「估」
- **無車位**：兩者相同（總價 ÷ 面積）

### 車位未拆價的估算

1. 每位車位價 ＝ 車位總價 ÷ 車位數（交易筆棟數的「車位 N」）
2. 依序找：同社區 → 同行政區 → 全市，同表別（買賣／預售分開）、同車位類別、交易日前後 1 年的每位車位價中位數；樣本數門檻分別為 3、5、5 筆，全市仍不足時用全市全期
3. 估算車位價 ＝ 中位數 × 車位數
4. 車位面積為 0（面積併在建物裡）時，同樣方法估每位車位面積再扣除
5. 卡片「原始欄位」的「車位估價依據」寫明用了哪個樣本池、幾筆

## 特殊交易旗標

關鍵字清單在 `pipeline/special_keywords.csv`（可直接改檔，下次排程生效）。比對「備註」欄。

| 旗標 | 預設 | 依據 |
|---|---|---|
| 親友關係、協議價購、政府標售、繼承標售、僅車位、持分、毛胚、瑕疵凶宅、急買急賣、債權債務 | 排除 | 備註關鍵字（避開「除海砂、輻射、凶宅外」等免責條款、車位持分等誤判，見單元測試） |
| 增建、頂樓加蓋、陽台外推、夾層、未登記建物、含傢俱裝潢、含稅費、含租約、露台 | 只標示 | 備註關鍵字 |
| 預售交屋 | 排除 | 買賣表備註「預售屋、或土地及建物分件登記案件」：交易日期是當年簽約日，與預售表重複 |
| 解約 | 排除（另有開關） | 預售表「解約情形」有值 |
| 整棟 | 排除 | 住宅大樓、華廈、公寓、套房、辦公且移轉層次為「全」；透天厝整棟是常態，不算 |
| 多棟 | 排除 | 交易筆棟數「建物」≥ 2 |
| 無單價 | 排除 | 總價或面積缺漏 |
| 合宜住宅 | 排除 | 政府合宜住宅配售（資格限定、價格遠低於市價）。備註空白、沒有建案名稱，只能用「土地段別＋簽約期間」辨識，清單在 `pipeline/rules.py` 的 `AFFORDABLE`；目前一筆：A7 合宜住宅（龜山區牛角坡段樟腦寮小段，2013 年 7–9 月配售約 2,600 戶，每坪約 14 萬）。5 年後的轉售是一般交易，不算 |
| 車位未拆價、車位面積未拆、單價估算 | 只標示 | 計算時產生 |

不進地圖與統計：純土地、純車位（交易標的不含「建物」）；交易日期早於 1990 年或晚於今天 31 天以上（打錯，例如 2101 年）。

統計（統計卡、社區頁、建案頁、走勢、比較）另外只算住宅型態：住宅大樓、華廈、公寓、透天、套房（店面、辦公等不算）。

## 定位精度

| 代碼 | 名稱 | 說明 |
|---|---|---|
| 1 | 門牌 | 桃園市門牌位置坐標資料直接命中棟級門牌 |
| 2 | 鄰近門牌 | 同巷弄同側 ±10 號內最近的門牌；預售「XX號旁」也算這級；預售建案以土地地號連結到交屋後的社區（見下節）也算這級 |
| 3 | 交叉口 | 「A路與B路交叉口」：門牌資料兩路最近點的中點，或 OpenStreetMap 交叉節點 |
| 4 | 巷弄 | 巷弄中心或同巷弄最近門牌（超過 ±10 號） —— 前端標「概略位置」 |
| 5 | 路段 | 路段中心，或預售建案「同地段推估」（見下節） —— 前端標「概略位置」，可能差數百公尺 |
| 9 | 未定位 | 不上地圖，列表與統計仍可見（依行政區篩選時） |

定位結果存在 `data/geocode_cache.csv`（只新增、不改寫）：鍵（`B|區|路|巷|弄|號` 為買賣棟級門牌，`A|區|地址` 為預售地址）、緯度、經度、精度、來源、門牌資料月份、日期、對應門牌、版本（比對規則改進時加 1，之前失敗的地址會重比）。

### 預售建案定位補強（建置時計算，不寫快取）

預售地址常只寫「XX段YY地號」或新路口，門牌資料還沒有。兩個補強方法都用土地明細（`h_lvr_land_*_land.csv` 的「土地位置」＝地段、「地號」）：

1. **地號連結交屋社區**：預售建案的地號與買賣成交的地號相同 → 那就是交屋後的社區。同一建案至少 2 筆、且過半指向同一社區才採用。建案位置改用該社區的門牌坐標（精度 2），並取得交屋後的實際公設比中位數（建案頁、比較表的「公設比（交屋後）」）。2021 年前的預售地址多半只有地號，這是舊建案唯一精準的定位方式
2. **同地段推估**：還沒定位、也還沒交屋的建案，找同一地段、地號母號相差 ≤ 60、已精準定位（精度 ≤ 3）的建物，取母號最接近的 5 棟，用緯度、經度中位數當位置（精度 5「概略位置」）；這 5 棟離中心最遠超過 500 m 就放棄（太散，寧可不猜）。每次建置會拿已知位置的建案假裝不知道位置來推估，在建置紀錄印出誤差

## 推定社區

- 同一棟級門牌（去樓層）＝同社區
- 不同門牌但距離 ≤ 80 m、建築完成年月與總樓層數都相同 → 合併（概略位置的棟不參與）
- 預售屋以「區＋建案名稱」為單位
- 社區名稱：代表門牌＋「等 N 棟」
- 手動合併／拆分：在 `data/manual/communities.csv` 寫「門牌鍵,社區代號,社區名稱」（門牌鍵見成交卡片「原始欄位」）

## 前端資料檔（`web/public/data/`，建置時產生，不進 repo）

每區拆兩段：`r`＝近 12 月（以資料最新成交日回推，預設期間），`o`＝更早（近 3 年內）。
前端先載各區 `r`；選「近 3 年」或自訂到更早的期間時才載 `o`。檔名含內容雜湊 8 碼，內容不變檔名就不變，手機可長期快取。

| 檔案 | 內容 |
|---|---|
| `meta.json` | 格式版本（`version`，前端版本不符會自動重新整理）、期別、更新時間、筆數、近 12 月起日（`split`）、近 3 年範圍（`range`）、2012 起全部範圍（`rangeAll`）、欄位順序、旗標表、型態與車位類別清單、各區各段檔名、歷史檔／搜尋／季統計檔名 |
| `tx/<區代碼>.<r或o>.<雜湊>.json` | 成交：`fields` 給欄位順序、`rows` 為陣列；`comms` 為這個檔用到的社區（欄位見 `commFields`），`cid` 指向 `comms` 的列號 |
| `detail/<區代碼>.<r或o>.<雜湊>.json` | 原始欄位（成交卡片展開時才載入；2012 起的舊成交沒有原始欄位檔） |
| `ent/<00–63>.<雜湊>.json` | 社區頁、建案頁用：每個社區／預售建案 2012 年起的全部成交，依代號雜湊（sha1 取餘數）分 64 份，點開社區頁才下載自己那一份（數百 KB）。`ents` 以代號為鍵：`c` 為社區列、`rows` 為成交（欄位同 tx，`cid` 固定 -1） |
| `search.<雜湊>.json` | 搜尋索引：每個社區／建案一列（欄位見 `searchFields`：代號、名稱、行政區、位置、是否預售、成交筆數、最後成交年月、歷史檔份號） |
| `stats.<雜湊>.json` | 季統計：各區＋全市 × 類別（大樓華廈、公寓、透天、套房、預售）× 季，扣車位單價 P25／中位數／P75 與件數。排除預設特殊交易；預售只算住宅型態；2012 年第 3 季起（實價登錄 2012/8/1 上路，更早的日期多為補登或打錯） |

社區欄位：代號（`c` 開頭為推定社區、`p` 為預售建案、`m` 為手動）、名稱、行政區、位置、完工年月、總樓層、棟數、是否預售、歷史檔份號（`shard`）、交屋後的社區代號（`link`，預售建案才有）、交屋後公設比中位數（`pr`）、位置精度（`level`）。

## 社區頁、建案頁、走勢、比較表的算法

| 項目 | 算法 |
|---|---|
| 進統計的成交 | 排除預設特殊交易、算不出單價的、非住宅型態 |
| 單價時間散布圖 | 每點一筆成交（扣車位單價），點色＝樓層三等分；灰帶＝近 3 年中位數 ±20%，帶外為異常值 |
| 異常值標示 | 偏離同社區中位數 ±20% 以上，卡片標「比社區中位 +N%」。買賣、預售分開算，同社區至少 4 筆才算；地圖列表用目前載入的資料（預設近 12 月，選近 3 年時含更早），社區頁用近 3 年 |
| 樓層價差 | 2 樓以上（1 樓常是店面或有庭院）各樓層的中位單價，以件數加權做最小平方回歸，斜率＝每高一層加價（萬/坪）；至少 3 個樓層才算 |
| 虛擬銷控表 | 解析預售「棟及號」：`A棟1-6F號` → 直欄 A-1、6 樓；`B棟B2-03F號` → B2、3 樓。同一戶多筆（解約後再賣）取最新一筆未解約的。格色＝建案內單價 5 分位（藍＝較便宜、紅＝較貴），灰＝解約，空白＝尚無成交。2021 年前的預售沒有棟及號，解析成功不到一半時不顯示 |
| 每月成交戶數（去化） | 預售依簽約月份，不含解約 |
| 解約率 | 解約件數 ÷ 全部預售件數 |
| 行情走勢 | 季中位數＋P25–P75 帶，成交量另畫一張（不同刻度不擠同一張）。行政區與全市用季統計檔，該季不到 10 件不畫線（表格仍列出）；社區、建案用歷史檔即時計算，建案一律用預售成交 |
| 比較表：預售 vs 新成屋 vs 中古屋 | 目前範圍，套用篩選但不限類別與屋齡；新成屋＝屋齡 ≤ 5 年，中古屋＝屋齡 > 5 年；「比中古屋」＝中位單價 ÷ 中古屋中位單價 − 1 |
| 比較表：多建案並排（最多 6 個） | 中位單價、近 12 月中位、P25–P75、車位價中位（單一車位、有拆價的成交）、公設比（交屋後）、解約率、每層加價 |

## 樓層三等分

低樓層：樓層 ÷ 總樓層 ≤ 1/3；中樓層：≤ 2/3；高樓層：其餘。缺總樓層或地下層不分類。

## 租賃（Phase 3）

只做近 3 年（2020 年前每年只有一、兩千筆）。來源是同一批期別 zip 的 `h_lvr_land_c.csv`，以編號去重、新的覆蓋舊的；定位與買賣共用棟級門牌快取。

| 項目 | 算法 |
|---|---|
| 月租（`rent`，元） | 總額元 − 車位總額元（有拆價時）；車位沒拆價就照總額，標「含車位」 |
| 坪數（`pg`） | （建物總面積 − 車位面積）× 0.3025 |
| 每坪月租（`ru`，元/坪） | 月租 ÷ 坪數；地圖色階、統計都用這個 |
| 毛租金報酬率 | 同範圍「整層住家」（出租型態：整棟(戶)出租、分層出租，住宅型態）每坪月租中位數 × 12 ÷ 同範圍買賣（不含預售）扣車位單價中位數 × 10,000。任一邊不到 5 件時顯示「樣本不足」；統計卡括號內為（租約件數／買賣件數） |

| 租賃旗標 | 預設 | 依據 |
|---|---|---|
| 社宅包租代管 | 排除 | 「租賃住宅服務」為社會住宅代管或社會住宅包租轉租（租金約市價 8 折）；近 3 年約占 78% |
| 親友關係 | 排除 | 備註有「親友」「員工」「特殊關係」 |
| 租金異常 | 排除 | 每坪月租低於 50 元或高於 5,000 元，或坪數不到 1 坪 |
| 含車位 | 只標示 | 租約含車位 |
| 非整層 | 只標示 | 套房、雅房（不進報酬率） |

前端租賃檔：`rent/<區代碼>.<雜湊>.json`，欄位 `id, d（租賃日 yyyymmdd）, lat, lon, geo, addr, cm（社區代號，同棟有買賣紀錄才有）, bt, fl, tf, age, rm, hl, ba, pg, rent, ru, rt（出租型態索引）, sv（租賃住宅服務索引）, fu（附傢俱 1/0）, mg（管理員）, el（電梯）, pt（車位類別）, pp（車位月租）, fx（租賃旗標位元）`。meta.json 的 `rent` 有欄位、出租型態、旗標表與各區檔名。租賃模式只套用篩選中的期間、行政區、型態、房數、坪數與「排除特殊交易」。

## 估價助手

| 條件 | 預設 |
|---|---|
| 期間 | 資料最新成交日往前 24 個月 |
| 範圍 | 半徑 500 m；不到 5 件自動放大到 1 km |
| 型態 | 與輸入相同 |
| 屋齡 | 輸入 ±5 年（留空不限） |
| 坪數 | 權狀（不含車位）±20%（留空不限） |
| 交易 | 只用買賣（不含預售），排除預設特殊交易與預售交屋紀錄 |

合理區間＝勾選中比較案例扣車位單價的中位數與 P25–P75；總價＝單價 × 坪數，勾「含一個車位」時再加比較案例中單一車位、有拆價成交的車位價中位數（不到 3 筆就用 1 km 內同期全部買賣）。輸入樓層時另列同樓層分類（三等分）的中位單價。條件與剔除的案例寫在網址（`vq`、`vx`），分享出去打開時用最新資料重算。

## 新成交提醒

- 收藏的社區、建案：記下收藏時（或上次開啟時）的 2012 年起成交筆數，搜尋索引的筆數變多就提醒
- 收藏的範圍（圓或多邊形）：記下範圍內近 12 月成交的編號，出現沒看過的編號就提醒（因為登錄有延遲，比對編號而不是比日期）

## 預售 → 成屋追蹤

- 建案連結交屋社區：先用土地地號（見「預售建案定位補強」）；連不到時，精準定位的建案 80 m 內、總樓層數相同、完工年月不早於開賣月份的社區只有一個時才連
- 同一戶：買賣表的「預售交屋」紀錄記的是當初的預售簽約價，與之後同門牌（含樓層）的一般買賣配對，列出總價漲跌與持有年數

## 圖層

| 圖層 | 來源 | 做法 |
|---|---|---|
| 土壤液化潛勢（初級、中級） | 國土測繪中心 WMTS（`SoilLiquefaction`、`SoilLiquefaction2`），資料為經濟部地質調查及礦業管理中心 | 直接疊圖磚；空白處是未列入潛勢區，不代表沒有風險 |
| 淹水潛勢（24 小時 500 毫米、6 小時 150 毫米） | 桃園市政府水務局「第三代桃園市淹水潛勢圖」shapefile（政府資料開放授權條款－第1版） | `python -m pipeline.layers flood`：40 m 網格掃描填色、同級相鄰格合併成矩形、用門牌座標的 1 km 格裁掉桃園市以外；未滿 0.3 m 不畫 |
| 車站、學校、公園 | OpenStreetMap（ODbL） | `python -m pipeline.layers osm`：一次抓取，原始回應存 `data/raw/osm/`，只留桃園市範圍；機場捷運只認桃園捷運路網 |

圖層檔存在 `data/layers/`（進 repo），建置時複製成含雜湊的 `layers/*.json`；資料來源更新時再手動重跑上面的指令。
